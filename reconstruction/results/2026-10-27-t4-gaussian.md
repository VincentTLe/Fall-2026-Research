## 1. Result

**Step 1.** The nerfstudio + gsplat + COLMAP toolchain works. With no phone video, the nerfstudio sample `poster` was
used. Its original link is dead, and the Hugging Face copy has only 100 of its 226 frames. COLMAP posed 98 / 100 frames,
and splatfacto reaches PSNR 35.1 on held-out frames after about 10 min.

**Step 2, m4c.** GaussianAvatar reproduces. The authors' checkpoint through the same `eval.py` gives
28.83 / 0.9759 / 0.0230, matching the paper's 28.78 / 0.9755 / 0.0228. The README command trains our own model to
**28.57 / 0.9740 / 0.0285**, 0.26 dB below the released checkpoint. The released checkpoint was trained about 5× longer
than the README command implies: 54,450 optimizer steps and LR milestones that correspond to `epochs=1000`, against
11,000 steps for us. Retraining with `--epochs 1000` and nothing else changed gives **28.80 / 0.9760 / 0.0225**,
level with the authors' checkpoint (28.83 / 0.9759 / 0.0230): 0.03 dB lower PSNR, slightly better SSIM and LPIPS.
So the 0.26 dB gap was training length. The README's 200-epoch command under-trains compared with the released
checkpoint. The gain is spread across training: 28.66 at epoch 200, 28.84 at 800, 28.80 at 1000. Rendering runs at
about 38 fps at 1080×1080, so it's real-time. Training took about 60 min, twice the paper's
"∼30 min" on a 3090.

**Step 2, neuman_bike** (phone video of a walking person). Scored the way GaussianAvatar's released code does it,
with the raw input poses for the test frames, our model gets **23.92 / 0.9600 / 0.0267** on 11 held-out frames. That
is far below the paper's NeuMan average of 29.94. The gap is almost all pose. Training corrects the poses of the
training frames, but nothing corrects the test frames. Refining the 11 test poses against their images, with the avatar
frozen and corrections of the same size the method applies to training poses (mean 3–5° per joint), raises the score
to **29.43 / 0.9767 / 0.0151**. InstantAvatar's published refinement settings (lr 1e-5, 20 steps) barely move the
poses (0.0002 rad) and give 24.00.

**Which row is comparable to the paper:** neither can be confirmed.
- The paper's NeuMan protocol is not described. Its text says nothing about test poses or test frames, and its code
  has no test-time refinement.
- The test frames are the ones the authors held out, and they match NeuMan's own split rule.
- The raw-pose row is what the released code and data produce.
- The paper's 29.94 is a 4-sequence average and sits close to our pose-corrected row. That suggests corrected test
  poses, but this is a guess.
- The refined rows fit poses on the test images themselves, so they are optimistic by construction. **Step 3 (REHAB24-6)** was skipped. It needs InstantAvatar-style preprocessing
(masks, SMPL fitting) with new third-party code and models, which Tan has not approved.

the size the method itself applies to training frames.

Where the protocol comes from (read 2026-10-28):
- **GaussianAvatar paper** (arXiv 2312.02134v3, Sec. 4.1): "we select four sequences (bike, citron, seattle, jogging)
  ... We initialize the estimated poses with an off-the-shelf method [ROMP]". It says nothing about test frames or test
  poses. "We follow the same evaluation protocol outlined in InstantAvatar" is said only for People-Snapshot.
  GaussianAvatar code: no test-time refinement (`eval.py` renders the shipped test poses).
- **InstantAvatar paper:** no NeuMan evaluation. On People-Snapshot it uses Anim-NeRF's poses, which were optimized
  for training *and test* frames beforehand. **InstantAvatar code** `eval.py` + `confs/SNARF_NGP_refine.yaml`: freezes
  everything except the SMPL pose embedding and fits the test frames (`optimize_SMPL.lr: 1e-5`, `max_epochs: 20`,
  NGPLoss = RGB MSE + 0.1 alpha MSE + 0.1 reg), then scores them.
- **NeuMan code** (`data_io/neuman_helper.py`, `create_split_files`): every 5th frame from index 2 is held out; the first
  half is "test", the second half "val". For bike's 104 frames that gives test = 2, 7, …, 47 and **val = 52, 57, …, 102**.
  That is exactly the 11 frames the authors' export leaves out, so the authors trained on NeuMan train + test (93)
  and held out NeuMan val. ml-neuman's own test-time pose optimization is an empty stub.

## 5. Checks

- **Step 1:** five frames of the orbit video and one held-out GT|render pair viewed. The poster text is readable and
  there are no floaters. In-training eval and `ns-eval` agree. Every data file matches its Hugging Face hash.
- **Eval protocol reproduced before trusting our numbers.** The authors' checkpoint, run through `eval.py` on this server,
  gives 28.83 / 0.9759 / 0.0230. Their shipped renders scored by our independent script give the same. Both match the
  paper. So data, environment, SMPL files and metric code are consistent with the authors'. The remaining difference
  is in training.
- `image_metrics.py --self-check`: identical images give PSNR > 80 dB and LPIPS 0, a constant 0.1 offset gives exactly
  20.000 dB, and LPIPS(normalize=True) on [0,1] equals LPIPS on the same images mapped to [−1,1] (0.132521 both). On
  all five m4c evaluations it agrees with `eval.py` to the printed digits.
- **LPIPS convention:** GaussianAvatar feeds [0,1] images to torchmetrics LPIPS, whose default expects [−1,1]. The paper
  matches the as-is value (0.0230), not the normalized one (0.0300). The table reports both.
- **Pose optimization:** in all three checkpoints the per-frame pose and translation embeddings equal the shipped
  `smpl_parms.pth` exactly (Δ = 0). The default `pose_op_start_iter=1800` is counted in epochs (`train.py:93`), so it
  never starts within 200 epochs, for us or for the authors.
- **Training length:** authors' checkpoint `scheduler.last_epoch` = 54,450 and milestones [333, 666]. In this code,
  milestones = [int(epochs/3), int(2·epochs/3)] (`arguments/__init__.py:142`), so they trained with `epochs=1000` (about
  990 × 55 steps). Ours: 11,000 steps, milestones [66, 133]. Both end at the same learning rates (3e-5, 5e-6).
